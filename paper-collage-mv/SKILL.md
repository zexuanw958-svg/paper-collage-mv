# 纸艺拼贴歌词 MV

输入一首歌（或片段），输出一支 1920×1080、24fps、带原音轨的 MV。画面是纸艺拼贴：每样东西都像从彩纸上剪下来，带一圈白纸边和淡投影，叠在水彩背景上，再统一加光、颗粒和暗角。歌词是奶白小纸片宋体字，逐字比演唱早一点落下。人物是 2.5 头身的剪纸木偶。

要做到的水准，先看 `assets/bar/第五轮medium-全片.jpg`（定版那支，《只对你有感觉》第五轮）。`assets/bar/` 里有参考片截图（`参考片-*`、`人物对照-参考片vs第五轮.jpg`）的话也看；公开仓库不带这几张第三方截图，没有就只看定版。这些图只用来对齐工艺，里面的角色和母题不要照搬。

本文件里的路径都相对 skill 目录（`SKILL_DIR`，就是这个 SKILL.md 所在的目录）。

命令按 macOS 的写法给。在 Windows 上照样跑这些脚本，变量和路径改成 PowerShell 的写法（比如 `$S = "<skill 目录>\scripts"`）；不是 Apple 芯片的电脑，对歌词时间时会自动换成 faster-whisper 在 CPU 上听写，慢一些，第一次要下载约 1.6 GB 模型。

第一次跑要从 Hugging Face 下载听写模型。下载一直不动（国内网络常见，`.incomplete` 文件停在 0 字节）时，停掉重跑，跑之前设环境变量 `HF_ENDPOINT=https://hf-mirror.com` 走国内镜像；开着代理时镜像会把请求转回 Hugging Face，这种情况让这条命令不走代理。

**这份 skill 是写给 Codex 这类照着流程做的执行 Agent 的。** 联调第 13 轮拿同一首歌做了三组对照：不用 skill 的 Codex 交出来像幻灯片；同一个 Codex 用了 skill，做工和镜头最好；不用 skill、只被告诉「放开手去做」的 Claude 和它打平。所以如果你是 Claude：下面的流程、分镜格式和创意上的硬要求不用照着走，只把这里的脚本和引擎当工具用：切抖音尾音、取歌词、逐字对齐、纸艺引擎、渲染和检查。创意、分镜、节奏和自查都自己定。交付规格照旧：1080p、24fps、带原音轨，歌词宁早勿晚，渲染走排队锁。

## 交付物

工程目录下要有这些：

- `out/<歌名>MV.mp4`：带音轨，时长等于 `work/song.wav` 的长度
- `STORYBOARD.md`：一句话创意、母题、人物设定、色调弧线、歌词上屏方案、分镜表（第一列是这段唱的歌词）
- `out/check/每句一帧.jpg`（每句歌词唱完时一帧，看画面是不是在演这一句）、`out/check/全片.jpg`（约每 2 秒一帧）、`out/check/对照定版.jpg`（你的全片和定版全片上下拼在一起）、`out/check/人物对照.jpg`（你的人物设定图 + 参考片人物截图拼在一起）和 `out/check/道具.jpg`（每样会进戏的道具和它的几个状态）
- 最后的中文回报，写清这几项：创意一句话；挑三句歌词，各说画面上是哪件事在演它；人物怎么设计的；主要道具有哪些、怎么让人一眼认出来；歌词怎么上屏；转场各用了什么、各属于哪一类做法；这首歌哪里唱得疏、哪里密，戏的疏密怎么跟着它（`motioncheck`「回看」列出的几段，各说一句为什么这样）；最好看的 2–3 帧（附时间点）；你对照参考片给人物质量打几分、差在哪；`camcheck` / `lyricscheck` / `motioncheck` 的结果；还没修好的问题；总用时。

## 流程

### 1. 备料（脚本都用 `uv run` 跑，依赖会自动装；第一次跑要下载模型，之后有缓存）

```bash
S=$SKILL_DIR/scripts
uv run $S/prep_audio.py <输入> work/song.wav --info work/song_info.json      # 转 wav、测 bpm 和能量；是抖音导出的会自动切掉水印尾音
uv run $S/fetch_lyrics.py --name <歌名> [--artist <歌手>] --out work/lyrics.txt   # 网易云取整首歌词（带原曲时间戳）
uv run $S/lyrics_timing.py --audio work/song.wav --lyrics work/lyrics.txt --out work/lyrics_timing.json --title <歌名> --work work/lyr
```

- 歌名从文件名或用户的话里取。拿不准是哪首歌、或者搜出来好几首同名歌，先跑 `lyrics_timing.py --audio work/song.wav --transcribe-only` 看听写，再用听到的一句 `fetch_lyrics.py --query "<那句>"` 搜。候选里优先选原唱，它的时间戳最准；有一句对不上就换 `--pick N`。
- 普通歌曲原样转换。只有从抖音导出的音频结尾才带约 3 秒水印（硬切、静音、一声「抖音」），脚本认出这个特征才会切，打印 `douyin_tail: true`；没有就是 `false`，不用管。
- 给的是整首歌（超过约 70 秒）时，先问用户要哪一段；没人可问就取第一段副歌连同它前面的一段主歌，约 40–60 秒，用 `--start 秒 --max 秒` 截。这套流程按 1 分钟以内的片段设计，整首歌渲染和打磨都要翻好几倍时间。
- `lyrics_timing.py` 打印的表里，「⚠」行要复核。来源是「听写估」「时间轴估」的，或对齐分很低的，用 `--env 起:止` 看人声响度包络（开唱处响度会突然抬升）。确认有错就直接改 json 里那几个字的 `t`。规矩是**宁早勿晚**：拿不准时取更早的时间。做法和常见错法见 `references/lyrics.md`。
- 片段里唱到的歌词由脚本自动挑；片段从半句开始或在半句结束时，没唱到的字会被裁掉。
- **连着一大段对不上**（好几句都报 ⚠，听写出来是乱码、广告词、「字幕志愿者」这类幻觉）时，先确认那里唱的到底是不是这些词，不要按人声响度把歌词硬摆上去。抖音的 DJ 版常常在中间接一段英文说唱或别的歌。用 `--transcribe-only --lang en` 再听一遍那一段。确认不是这首歌的词，就照实处理：听得出的那几句照常上字，换了词的那段按实际唱的上字或者不上字，回报里写清楚。确认就是这些词、只是听不清，才按人声起音手工对。

### 2. 建工程

```bash
uv run $SKILL_DIR/scripts/new_project.py <工程目录> work/song.wav work/lyrics_timing.json work/song_info.json
cd <工程目录> && node render.mjs --sheet=0.5,2,4 --out=out/check/hello.jpg   # 看到示例画面就说明环境通了
```

建完工程以后，歌词时间以工程里的 `assets/lyrics_timing.json` 为准，`work/` 里那份不再生效。要改哪个字的时间，改工程里这份，再跑 `lyrics_to_js.py`（见 `references/lyrics.md`）。

下面的 `node render.mjs`、`node tools/...` 都在工程目录里跑。工程里有这些：`studio.html`（页面入口，按顺序加载 `src/` 下的脚本，加新文件要在这里登记）、`src/paper.js`（纸艺引擎）、`src/lyrics.js`（歌词字卡）、`src/puppet.js`（剪纸木偶和表演关键帧 `act`）、`src/fx.js`（弹出、余震、反应符号、环境动效，和围巾、门这类道具的零件）、`src/scenes/example.js`（6 秒的示范：他趴在窗边泄气，她从窗外溜过来敲玻璃、举起风车逗他、又藏到背后，最后递进窗。学它的写法：全身姿势、一前一后站、窗框当画框、镜头横移、道具在两人手里传；文件末尾的 `LOOPS.props` 是道具设定图的写法，摆了围巾、门、风车三种做法。别学它的内容，换成你自己的场景后删掉）、`render.mjs`（渲染、抽帧、拼图）、`tools/camcheck.mjs`、`tools/lyricscheck.mjs` 和 `tools/motioncheck.mjs`。引擎 API 和用法见 `references/engine.md`。第五轮的部分源码在 `examples/`（`kids.js` 是 `puppet.js` 的原型，`props.js` 是道具，`scenes/` 是场景），**学它的结构、工艺和怎么把一件事演细，角色长相和母题要自己设计**。

### 3. 写 STORYBOARD.md，不用等人审，写完就开工

动笔前先读 `references/philosophy.md`：这类 MV 怎么想，为什么定版看着是活的。先听懂这首歌：情绪、讲话的人是谁、每一句在唱什么事。再定一个点子贯穿全片。创意上只有下面几条硬要求，其余放开做：

- **每一句都要在画面上发生。** 唱到哪句，画面里就在演哪句：这句的意思变成人物此刻做的一件事，或者世界的一个变化，在唱到那个词的时候落下。定版里唱「我就收敛」，荡得正疯的秋千停住、他乖乖坐好；唱「又是晴天」，她头顶的雨云翻成太阳。母题和人物是把句子串起来的线，不是另编一个故事再铺到歌上。作者看联调成片时指出：定版的每个画面都在演那一句歌词，Codex 却按整段歌词的意境自己编一个故事，再铺到歌上（`references/philosophy.md`「歌词就是剧本」）。
- **一个母题贯穿到底，首尾呼应，结尾兑现。** 第一秒就要有强图形，紧接一个揭示。母题是一条线：开场亮出来，在几个转场里出现，结尾兑现，**不是每个镜头都摆着它**。中间几段各有各的世界（地点、道具、光），人物在里面做事。定版那条的东南西北只在开场、两三个转场和结尾出现，中间六七段各是一个不同的地点。这首歌的世界从它自己的歌词和情绪里找，别搬定版的，也别用放进哪首歌都成立的布景（联调里屋顶晾衣场、温室、电车站几乎每支都有）。
- 母题从这首歌自己的歌词里长出来，换一首歌就不成立才对。定版的东南西北来自「心像海底针」那句：猜不透，所以玩一个猜心的折纸游戏。唱片、磁带、耳机、音符这类「音乐本身」的东西放到哪首歌都成立，不要当母题。也别直接拿歌词里的那个名词当母题：两个模型各做各的，都把「看不清那张合影」做成了一张合影，点子撞成一样。这条只管母题，单独一句里用这句自己的东西把它演出来是对的。先用一句话说出那句的情绪，再找东西装它；写三个点子，挑最只属于这首歌、又最不直白的（`references/philosophy.md`「母题要绕一步」）。
- **每句都演，但别演成一张张平的情景剧画面。** 早期有一版每句歌词配一个情景剧画面，作者嫌不惊艳：嫌的是画面平，不是画面跟着歌词。惊艳来自：镜头尺度反差大（大脸特写 ↔ 大世界里的小人）、每一段一个有光的色调世界、一个点子用到底。
- **转场要丝滑，每次换一种做法**：用戏里的东西完成。做法分几类：推进匹配（推到一样东西占满画面，切到下一场形状对得上的东西再拉出来）、跟着东西走、动作接动作、世界本身像纸一样折起翻开撕开、遮挡和开孔。同一类全片最多用两次，这是上限不是配额；换盖屏的道具、换孔的形状不算换（`references/philosophy.md`「转场」）。推进匹配是穿过去，满屏只剩那样东西的时候只停几帧。中途前后两个画面，或者带过去的那样东西，要一直看得见，不能整屏只剩一块平涂。转场后人物要么本来就在，要么用动作进场，不用半透明淡入淡出。全片硬切最多两三处，不用闪白。
- 已经用过的母题别再用：东南西北折纸、心动纸蝶、小指红线、灰色世界里只有一个人是彩色的、海底针、钓心。
- **每段是一出小戏**：每个人物写一句性格。分镜表第一列写这段唱的歌词，逐句列出来；每句旁边写画面上哪件事在演它、落在哪个词上。再给每段写一小段话：谁想要什么、做了什么、出了什么岔子或惊喜、对方怎么接、落在什么情绪上（每换一次表情，都写得出是哪件事引起的），要能用一串动词讲出来，而且主要靠身体（探、仰、塌、蹦、转身、凑近、碰到对方），不是靠挥胳膊。具体到哪一秒做什么，写代码时再定。定版开场是怎么写、怎么落到代码上的，见 `references/motion.md`。
- **每段写清怎么看、在哪里**：构图（景别；谁在前谁在后；用什么框住、什么挡在前景；镜头从哪儿走到哪儿），和这个世界里只属于它的具体东西（前、中、远三层各有什么，哪几样会进戏，哪些一直在轻轻动）。相邻两段的构图不要一样。

### 4. 先过人物关和道具关，再搭场景

人物用 `puppet(spec, x, y, s, P)` 搭：骨架、表情表、动作参数和一套全身姿势（`pose`：探身、吓一跳、蹲、欢呼、泄气、害羞、捧心、捂脸、背过身……）是现成的，长相（发型点列、配色、衣服细节、配饰）在 spec 里自己设计，写法见 `src/puppet.js` 顶部的注释。自己另写人物函数也可以，但要用 `actor(() => { ... })` 包起来，`motioncheck` 才认得出它是人物。

开工先把主角做成一张设定图（`LOOPS.sheet`）：正面、侧面、3–4 种表情、几个全身姿势。渲出来，和 `assets/bar/参考片-脸部放大.png`、`参考片-衣服放大.png`、`参考片-12帧总览.jpg` 拼成 `out/check/人物对照.jpg`，诚实打分（没有这几张，就和 `第五轮medium-全片.jpg` 里的人物比）。精致度没到参考片的水平就继续改，人物过关以后再搭场景。人物的工艺要点见 `references/craft.md`「人物」。

道具也一样。分镜里每样会进戏的道具（被拿起来、递过去、打开、戴在身上、倒下的）各写一个函数，在 `LOOPS.props` 里把它的每个状态摆一排（合上和打开、挂着和被风吹起、立着和倒下、拿在手里），渲成 `out/check/道具.jpg`。不看分镜，只看这张图问自己：给一个没看过这支片的人看，他能说出每样东西是什么吗？说不出的就重画：先改剪影，再加认得出的细节和材质。软的东西用 `strip` / `tail`，绕边翻的用 `flap`，见 `references/craft.md`「道具」。光、心意这类抽象的东西不当道具，换成一个装着它的实物。

### 5. 逐段搭，每段都自查

把每段的小戏拆成动作，写成 `act()` 关键帧（身体用 `pose`，一次性的小动作用 `hop`、`nod`、`headShake`、`stomp`），反应用 `fx.js` 里的 `jolt`、`mark`、`heartsUp`、`pop`。按 `render.mjs` 顶部的用法看画面：`--sheet`（挑几个时间点）、`--strip`（一段里的每一帧，看动作）、`--crop`（局部放大，看脸和手）。每段重点看四件事：歌词读不读得出、出现时机对不对、人物在不在演、表情有没有来由。表情是结果：每次换都因为刚发生了一件事，换了就拿住，底色跟着这句歌词的情绪（`references/philosophy.md`「表情有来由，换了就拿住」）。

「在演」是指这段真的发生了一件事，而且一个动作引出下一个：他翻开只有问号，泄气推开碗，她冒出来一把抢走，他吓一跳。只是并排站着、隔几秒抬一下手，或者每隔零点几秒均匀地抬手、点头、笑一下，都不算在演。每段搭完，静音看一遍这段的 strip（再想象把两只胳膊冻住，还看不看得懂），再跑 `node tools/motioncheck.mjs --from=a --to=b` 看一眼；哪里太静，就回到这段的戏里加一件事，不要加晃动。

### 6. 出片前全片检查

```bash
node tools/camcheck.mjs      # 运镜有没有来回冲（「一下放大一下缩小」一眼就看得出）
node tools/lyricscheck.mjs   # 每个字有没有按时上屏（晚了不行），有没有漏句
node tools/motioncheck.mjs   # 有没有整屏好几秒什么都没在动、转场中途画面空了、人物半透明；整首歌唱得疏还是密；各段动作密度、构图（含两人并排）、身体用了哪些部位；每段每个人换过的表情；画面有没有亮部；最后「回看」列出动作最满、最空的几段
```

三个检查的「必须修」项清零，「看一眼」也逐条看：构图连着几段一样、两人并排太多、人物都在正中、只动胳膊、镜头钉在原地，这几条看片的人都看得出来。`motioncheck` 的数字是报警器，不是要刷的分：它报哪里死了，就给那里加一件事，用一直晃的 `sin` 或者均匀的小动作凑数，一眼看得出。「表情」那几行对着歌词看：哪次换表情说不出原因，或者和这句的情绪对不上，就删掉，让上一个表情拿住。「回看」那几行每次都会列，改完也还在，不是报警：把那几段再看一遍，觉得对就留着，在回报里写一句为什么。三个检查都不报警，只说明没有明显的毛病，不说明好看。再全片扫一遍瑕疵：残影方块、转场残留（转场最后几帧逐帧看，残片会压在脸上）、穿模、手臂折角、错别字、漏掉的歌词、纸边在特写里变得太粗、同一个地面上两个人一大一小、转场中途整屏只剩一块没有纸纹的纯色、认不出是什么的道具（截一帧问自己：这是个什么东西）、半透明的人物。最后把每个转场按做法归一下类，同一类超过两次就换掉几个。

先看歌词和画面绑没绑上：`lyricscheck` 最后一行给了「每句一帧」的命令，跑出 `out/check/每句一帧.jpg`，每格只看画面和它的字卡，问两件事：画面上是不是正在发生这一句？把字卡换成这首歌的另一句，画面还说得通吗？说得通，就是这句没绑上，回第 5 步让这句的那个意思在画面上发生。

然后和定版比**信息量**：`node render.mjs --sheet=<每 2 秒一个时间点> --cols=5 --w=384 --out=out/check/全片.jpg`，再把它和 `assets/bar/第五轮medium-全片.jpg` 上下拼成 `out/check/对照定版.jpg`，一格一格对着看。定版 50 秒里有八九个不同的世界，每一格都有前、中、远景和几件道具，人物在每段都有事做，大脸特写和大世界里的小人轮着来。重点对这几样：

- **构图重复**：连续三四格构图差不多（同一个画面占了 6 秒以上），或者很多格都是两个人并排站在画面正中、镜头钉在中心推拉。
- **色调**：把 `全片.jpg` 缩小到一眼看完，和定版并排看：整体是不是比定版灰、比定版暗？这首歌该不该比定版暗？甜歌、暖歌要亮、通透，每个世界都有接近纸白的亮处（天光、窗、奶白的纸、灯的辉光），暗的只是投影和真该暗的那几段（`references/philosophy.md`「色调跟着这首歌走」）。
- **人物大小**：定版大多数格里人物占画面高度的一半上下，全片有四五格是脸或者一件道具占满大半个画面的特写。你的人物要是大多只占三分之一以下，「大世界里的小人」就不再是反差，是常态了。
- **世界有没有自己的东西**：每个世界要有只属于它的道具。好几段都拿同一套楼群、盆栽当背景，看起来就是一个世界换了颜色。
- **结尾**：最后一格要能直接当封面：母题在这里兑现，主角的脸清楚。歌里本来就是一个人（唱的是「没人陪」这类），结尾就是一个人，不用硬凑两张脸。

有一样差得明显，就回第 5 步把那几段改好，再出片。

### 7. 渲染和验收

```bash
node render.mjs --frames --workers=3        # 自带排队锁：别的工程正在渲，它会等那边渲完再开始，不用自己查
node render.mjs --encode --out=out/<歌名>MV.mp4 --audio=assets/song.wav
uv run $SKILL_DIR/scripts/check_mv.py out/<歌名>MV.mp4                             # 时长、音轨，并重出 out/check/全片.jpg 和 对照定版.jpg
```

成片出来后，再抽查开头、高潮、结尾和每个转场的 strip。返修时只改动的段落用 `--frames --range=a:b` 补渲（先删掉那段的旧帧），再重新 encode，不要整片重来。

### 8. 封面（用户要发布时才做）

封面上只放歌名，用 MV 里同款的字，不加宣传小字。底图用片里最有情绪的一帧，通常在结尾。比例按用户说的出（抖音常用 3:4）。

## 技术底线（违反就返工）

- **帧是 `t` 的纯函数**：渲染是多进程乱序的，不许在帧之间留状态，不许用 `Math.random`，随机数一律用 `hash(i)`。
- **人物不跟鼓点颠**：待机只慢呼吸、眨眼。表演是一个接一个有事的动作（第 3 步的小戏），不是跟着拍子上下颠，也不是一直晃。节奏交给镜头、换景和歌词。
- **歌词宁早勿晚**：`lyricLine` 已经按开唱时间提前 0.22 秒出字。自己在场景里画歌词时，用 `lyricAt(句, 字)` 定出现时间，并调用 `lyricMark`。
- **运镜单调**：主镜头一律用 `camK`（逐段 ease，缩放在对数空间插值）。想停一下，就放两个相同的关键帧。不要自己写会过冲的样条。
- **画面里除了歌词不放别的字**。反应符号「?」「!」和小心、闪光不算字，定版里用过。人物和主要物件不用黑色描边（纸艺风靠白纸边和投影出轮廓）。
- 画面全用代码画：不加载任何图片素材，不调用生图、生视频模型（这样「代码画出来的」这句宣传才属实）。字体只用 `assets/fonts/` 里的。
